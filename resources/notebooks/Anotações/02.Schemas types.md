# 📘 Definição de Schema no Apache Spark

Ao ler arquivos (CSV, Parquet, etc.) no Spark, definir corretamente o **schema** é fundamental para garantir **performance, consistência e confiabilidade** dos dados.

Existem **três formas principais** de trabalhar com schema no Spark:

---

## 1️ StructType (Schema explícito / manual)

###  O que é
Você define o schema **coluna por coluna**, informando explicitamente o tipo de cada campo.

```python
from pyspark.sql.types import (
    StructType, StructField,
    IntegerType, StringType, DateType
)

schema = StructType([
    StructField("ClienteID", IntegerType(), True),
    StructField("Genero", StringType(), True),
    StructField("Idade", IntegerType(), True),
    StructField("EstadoCivil", StringType(), True),
    StructField("RendaAnual", IntegerType(), True),
    StructField("Frequencia", IntegerType(), True),
    StructField("ProdutoPreferido", StringType(), True),
    StructField("DataCadastro", DateType(), True)
])

```
```
✅ Vantagens

Controle total dos tipos de dados
Evita erros de inferência
Melhor performance (Spark não precisa analisar os dados)
Padrão recomendado para produção

❌ Desvantagens
Código mais longo
Necessário conhecer o schema previamente
```
============================================================

## 2 Schema manual em formato texto (Schema String)

###  O que é
Uma forma mais simples e legível de definir o schema usando texto.

```python
schema = """
ClienteID INT,
Genero STRING,
Idade INT,
EstadoCivil STRING,
RendaAnual INT,
Frequencia INT,
ProdutoPreferido STRING,
DataCadastro DATE
"""
```

```
✅ Vantagens
Código mais curto e limpo
Fácil de ler e manter
Mesmo desempenho do StructType
Muito usado em projetos reais e em aula

⚠️ Observação importante
Internamente, o Spark converte esse texto em um StructType, ou seja, o comportamento é o mesmo.
```


============================================================

## 3 inferSchema=True (Inferência automática)

###  O que é
O Spark analisa os dados para tentar identificar automaticamente o tipo de cada coluna.

```python
spark.read.csv(
    "/caminho/arquivo.csv",
    header=True,
    inferSchema=True
)

```

```
✅ Vantagens
Código rápido de escrever
Útil para exploração inicial dos dados

❌ Desvantagens (importantes)
Mais lento (Spark precisa ler os dados para inferir tipos)
Pode inferir tipos incorretos
Pode gerar inconsistência entre arquivos
Não recomendado para produção
```
# Regra de ouro (mercado)
## Em ambientes de produção, NUNCA confie apenas em inferSchema. prefira definir o schema manualmente, porem caso presciso evoluir este schema o spark age muito bem e tem recursos incriveis pra isso .


## 4 Evolução de schema em Parquet (leitura e escrita)

###  O que é
```
O Spark consegue evoluir schemas, mas depende do formato do dado e do comando usado.
É quando o formato do dado muda ao longo do tempo
(ex.: nova coluna, coluna removida, tipo alterado) sem quebrar o pipeline.

✅ Onde o Spark evolui schema de verdade
🔹 Parquet → suporta
🔹 Delta Lake → suporta MUITO bem (recomendado)

```
```python
df.write \
  .mode("overwrite") \
  .option("overwriteSchema", "true") \ #Sobrescrever schema
  .parquet("/caminho/parquet")


```

```python

df.write \
  .format("delta") \
  .mode("append") \
  .option("mergeSchema", "true") \ #Adicionar novas colunas automaticamente
  .save("/caminho/delta")



```
